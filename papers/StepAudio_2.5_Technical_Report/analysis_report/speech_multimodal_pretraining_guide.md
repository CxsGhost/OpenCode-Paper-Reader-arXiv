# StepAudio 2.5 语音多模态预训练详解

> 本文档基于 StepAudio 2.5 Technical Report，系统梳理其语音多模态预训练的架构、数据、训练策略等核心内容。
> 适合正在做全双工多模态模型预训练/模态对齐的同学参考。

---

## 一、整体架构：Audio-Encoder → Adaptor → LLM-Decoder

### 1.1 核心设计思想

StepAudio 2.5 采用了当前音频-语言建模的主流范式：**音频编码器 + 适配器 + LLM 解码器**。这是一个「非对称」设计：

- **音频编码器（Audio Encoder）**：冻结状态，负责将波形特征转换为紧凑的声学嵌入（acoustic embeddings）。做的是稳定的声学抽象。
- **适配器（Adaptor）**：轻量级模块，将声学嵌入映射到 LLM 的隐空间。这是连接声学世界和语义世界的桥梁。
- **LLM 解码器（Decoder）**：从预训练的文本 LLM 初始化，承担语义理解、上下文管理、指令跟随和生成的核心任务。

### 1.2 为什么是非对称的？

这个设计刻意将语义的负担放在解码器端。好处是：一旦语义能力主要由解码器承载，下游不同的任务（ASR、TTS、Realtime 对话）就可以共享绝大部分模型参数，只在输出空间和解码策略上做差异化。

### 1.3 统一序列空间

解码器在一个统一的序列空间上工作，这个空间中同时存在：
- 传统的文本 token
- 新引入的音频 token（speech tokens）

模型不需要分别拥有「理解」和「生成」两种能力，而是拥有一个高质量的多模态先验（multimodal prior），加上将监督信号路由到不同输出空间的机制。

### 1.4 三个推理方向

同一个基座模型支持三种推理方向：

| 方向 | 输入 → 输出 | 核心挑战 |
|------|-------------|----------|
| ASR | 音频嵌入 → 文本 token | 输出空间窄且离散，受语音信号强约束 |
| TTS | 文本+控制指令 → 音频 token | 输出空间丰富，核心挑战是自然、表达性合成 |
| Realtime | 音频理解 + 响应生成（低延迟） | 维护对话状态、人设一致性、上下文得体性 |

### 1.5 对你项目的启示

如果你在做全双工多模态模型：
- 模型基座选择一个强大的文本 LLM 作为解码器初始化
- 音频编码器可以用现成的（如 Whisper encoder、Qwen3-Omni encoder），冻结即可
- 关键是中间的 Adaptor 设计和训练策略——它是模态对齐的核心组件

## 二、数据引擎：自动化数据生产流水线

### 2.1 流水线总览

StepAudio 2.5 采用了一套自动化数据生产流水线，同时为语音理解（ASR）、语音合成（TTS）和语音对话（Realtime）三个任务提供数据支撑。

### 2.2 处理步骤详解

**第一步：初步筛选**
- **SED（Sound Event Detection，声音事件检测）**：过滤非语音段
- **VAD（Voice Activity Detection，语音活动检测）**：检测有语音的片段

**第二步：分段与合并**
- 相邻的 VAD 片段进行合并
- 重新分割成具有相对完整语义、合适时长的基础样本（base samples）

**第三步：音频级标注**（对每个音频片段）
- 音频质量评分
- 合成语音检测（区分真人语音和合成语音）
- 说话人数量标注

**第四步：文本级标注**
- 使用双 ASR 模型进行转录
- 语言识别（Language ID）
- 转录结果交叉验证：通过 WER（词错误率）、编辑距离、语速等指标

**第五步：语义级标注**
- 基于 ASR 转录文本进行语义完整性评估
- 内容分类

**第六步：数据分级**
- 按语言、时长、语义质量分数、音频质量分数进行分类和分级
- 这使得预训练的不同阶段可以采样不同质量的数据

### 2.3 对你项目的启示

- **数据质量分级很重要**：不是所有数据用同一个标准，而是在不同训练阶段使用不同质量的数据
- **多模型交叉验证**：用两个 ASR 模型交叉验证转录准确性，而不是盲目信任单一模型
- **自动化标注管线**：如果你的数据规模大，一定要建自动化流水线，包括质量评分、说话人检测等
- **合成数据检测**：注意检测并标记合成语音，避免数据中的噪声

## 三、预训练分阶段策略（核心重点）

### 3.1 总览

StepAudio 2.5 从一个**文本 MoE（Mixture of Experts）LLM** 初始化，然后在 **2.2T tokens** 的文本和音频数据上进行持续预训练。训练遵循明确的分阶段配方（staged recipe）。

### 3.2 阶段一：Adaptor 对齐阶段（模态对齐）

| 项目 | 详情 |
|------|------|
| 数据量 | 3B tokens 的 ASR 数据 |
| 目标 | 将语音和文本的特征空间在 Adaptor 中对齐 |
| 冻结模块 | 音频编码器 ✅ 冻结，LLM ✅ 冻结 |
| 训练模块 | **仅训练 Adaptor** |
| 核心作用 | 建立初始接口，使声学特征可以被文本原生的解码器消费 |

**关键理解**：这个阶段的目的是让 LLM "学会读取"音频信号，但不改变 LLM 本身的能力。类似于给 LLM 装了一个"耳朵接口"。

### 3.3 阶段二：统一多模态训练（主训练阶段）

在对齐之后，模型执行两个关键操作：
1. **扩展词汇表**：加入 speech tokens（语音 token）
2. **开始统一多模态训练**：序列长度 16K

#### 数据配比
- **总量**：1600B tokens
- **文本数据**：800B tokens
- **语音数据**：800B tokens（即 1:1 配比）

#### 语音数据的任务类型
语音数据不只是做转录！包含多种输入-输出配置：
- ASR（语音→文本）
- TTS（文本→语音）
- Speech-to-text translation（语音翻译）
- Utterance-level text-speech interleaved continuation（句子级文本-语音交错续写）
- Speech-to-speech conversation（语音对语音对话）

**关键理解**：模型不仅仅把音频当作转录输入，而是作为**通用序列模态**出现在多种输入输出配置中。这是让模型真正理解"双向"音频-文本关系的关键。

#### 阶段 2a：Warmup 热身阶段

| 项目 | 详情 |
|------|------|
| 数据量 | 128B tokens |
| 目标 | 稳定新引入的语音词汇表，帮助 MoE 专家快速适应音频模态数据 |
| 学习率策略 | **分层学习率**（非常重要！） |

**分层学习率设置**：
- Adaptor、Embedding 层、Output 层：**较大学习率**（让它们快速适应新模态）
- MoE Router（路由器）：**较小学习率**（减少对文本模态的干扰）
- Base Model（基座）：标准学习率

**为什么这样做？** 新引入的语音词汇和嵌入需要快速学习，但路由器如果变化太快会破坏已学到的文本能力。这是"学新不忘旧"的工程手段。

#### 阶段 2b：主训练阶段

| 项目 | 详情 |
|------|------|
| 学习率 | 所有层的学习率统一回归到基准学习率 |
| 特殊处理 | MoE 辅助损失系数 + Router 学习率逐步退火（anneal） |
| 目标 | 维持专家利用率和 top-k 路由概率之间的平衡 |

### 3.4 阶段三：Cooldown 冷却阶段

| 项目 | 详情 |
|------|------|
| 数据量 | 600B tokens 高质量文本和音频数据 |
| 序列长度 | 增加到 **32K** |
| 新增数据类型 | Audio Caption（音频描述）+ Instruct TTS（指令式 TTS）|
| 强调重点 | 更高质量的多模态监督 + 长上下文能力精细化 |

### 3.5 完整训练流程总结

```
文本 MoE LLM（初始化）
    │
    ▼
[阶段1] Adaptor 对齐（3B tokens ASR 数据，仅训练 Adaptor）
    │
    ▼
  扩展词汇表（加入 speech tokens）
    │
    ▼
[阶段2a] Warmup（128B tokens，分层学习率，稳定新词汇）
    │
    ▼
[阶段2b] 主训练（~1472B tokens，统一学习率，Router 退火）
    │
    ▼
[阶段3] Cooldown（600B tokens 高质量数据，32K 序列长度）
    │
    ▼
  预训练完成 → 下游特化（ASR / TTS / Realtime）
```

### 3.6 预训练的本质意义

论文强调：预训练学到的不仅仅是音频和文本之间的"原始关联"，而是它们之间的**操作接口（operational interface）**。这个接口后续被三个方向复用：
- ASR：将音频证据映射为文本 token
- TTS：将文本语义映射为音频 token  
- Realtime：在低延迟约束下耦合听、推理和响应生成

### 3.7 对你项目的启示

1. **初始化很重要**：从一个预训练好的文本 LLM 开始，而不是从头训练
2. **先对齐，再联合训练**：不要一上来就全部放开训练。先只训 Adaptor（对齐阶段），确认音频信号能被 LLM 读取后，再开放更多参数
3. **分层学习率**：不同模块用不同学习率，保护已有能力的同时快速适应新模态
4. **数据多样性**：语音数据不要只做 ASR，要包含多种任务格式（ASR、TTS、翻译、交错续写、对话等），让模型理解双向关系
5. **Warmup 非常关键**：新词汇引入后需要一个稳定期，不能直接上大量数据
6. **高质量数据放后面**：Cooldown 阶段用高质量数据做精细化，类似于课程学习（curriculum learning）的思想
7. **MoE 模型的特殊考虑**：如果你用 MoE，要注意 Router 的学习率要比其他模块小，否则会破坏已有的专家分工

## 三（补充）、解冻策略与防止 LLM 语言能力退化

### 问题：Encoder 全程冻结，LLM 单方面适配不会训烂吗？

这是一个核心问题。StepAudio 2.5 的设计让 LLM 去适应冻结的 Encoder 输出，但通过多层防护机制确保语言能力不退化。

### 完整解冻策略一览

| 阶段 | Encoder | Adaptor | LLM Embedding/Output | LLM Base | MoE Router |
|------|---------|---------|---------------------|----------|------------|
| 1. 对齐（3B） | ❄️ 冻结 | 🔥 训练 | ❄️ 冻结 | ❄️ 冻结 | ❄️ 冻结 |
| 2a. Warmup（128B） | ❄️ 冻结 | 🔥 大LR | 🔥 大LR | 🔥 标准LR | 🔥 小LR |
| 2b. 主训练 | ❄️ 冻结 | 🔥 统一LR | 🔥 统一LR | 🔥 统一LR | 🔥 逐步退火 |
| 3. Cooldown（600B） | ❄️ 冻结 | 🔥 训练 | 🔥 训练 | 🔥 训练 | 🔥 训练 |
| ASR SFT | ❄️ 冻结 | 🔥 训练 | 🔥 训练 | 🔥 训练 | 🔥 训练 |

**关键结论**：Audio Encoder 从头到尾不解冻。不存在"解冻 Encoder + Adaptor"的阶段。

### 为什么 LLM 不会被训烂？——多层防护机制

**机制一：Adaptor 作为缓冲层**

```
Encoder (冻结，输出声学特征) 
    → Adaptor (学习"翻译"，把声学特征映射到 LLM 能理解的空间) 
        → LLM (看到的已经是自己隐空间里的向量)
```

LLM 不需要"大幅扭曲"自己去理解原始声学信号。阶段1结束时，Adaptor 已经完成了基本对齐，LLM 收到的音频嵌入已经在它熟悉的隐空间中了。

**机制二：文本与语音数据 1:1 配比**

这是最核心的防护手段：

| 数据类型 | 量 | 占比 |
|---------|-----|------|
| 文本数据 | 800B tokens | **50%** |
| 语音数据 | 800B tokens | **50%** |

LLM 在学习音频能力的同时，持续在文本数据上做语言建模。相当于一边学新东西，一边不断"复习"老本行。

**机制三：MoE 架构的天然优势**

MoE 模型比 Dense 模型天然更抗遗忘：
- 不同的专家可以"分工"——有些专家继续负责文本，有些逐渐学会处理音频
- Router 学习率小 → 原来负责文本的专家不会被突然分配去处理音频
- 等价于"保护旧有专家分工"

**机制四：分层学习率**

Warmup 阶段的分层策略：
- Adaptor/Embedding/Output 用大学习率 → 让新模态的接口层快速适应
- MoE Router 用小学习率 → 保护已学好的文本专家路由
- 效果：新能力集中在"新增"的参数空间学习，尽量不扰动已有的文本处理路径

**机制五：MoE 辅助损失退火**

主训练阶段中，MoE 辅助损失系数（auxiliary loss coefficient）逐步退火（anneal），维持 expert utilization 和 top-k routing 之间的平衡。这防止某些专家被"过度征用"到音频任务上，导致文本能力下降。

**机制六：Cooldown 阶段修复**

如果前面的训练阶段有轻微的能力退化，600B tokens 的高质量数据（文本+音频）可以做最后的修复和精细化。

**机制七：Dynamic Rehearsal Schedule（下游 SFT 阶段）**

在 Realtime SFT 阶段，论文额外使用了动态复习调度：

> 交互数据与通用指令数据、推理任务基于验证指标（validation metrics）持续交替。

这不是简单的固定配比，而是**根据验证集表现动态调整**——如果发现语言能力下降，就自动多混入通用数据。

### 防护机制总结表

| 机制 | 阶段 | 作用 |
|------|------|------|
| Adaptor 缓冲 | 全程 | LLM 不直接面对原始声学特征 |
| 文本:语音 = 1:1 | 预训练主阶段 | 持续维护语言能力 |
| MoE Router 小学习率 | Warmup | 文本专家分工不被打乱 |
| 分层学习率 | Warmup | 新模态集中在接口层学习 |
| MoE 辅助损失退火 | 主训练 | 防止专家被过度征用 |
| 高质量 Cooldown | 预训练末期 | 修复可能的轻微退化 |
| 动态复习调度 | 下游 SFT | 根据验证指标自动调配比 |

### 如果你用 Dense 模型（非 MoE）怎么办？

MoE 有天然的专家分工优势，如果你用的是 Dense 模型（如 Qwen2.5-7B、LLaMA 等），建议：

1. **文本数据占比更高**：考虑 60%~70% 文本 + 30%~40% 语音
2. **学习率更小**：整体学习率要比 MoE 设置更保守
3. **可考虑 LoRA / QLoRA**：先用参数高效方法做初步适配，验证音频通路打通后再考虑全量微调
4. **设置文本能力的验证基准**：在训练过程中持续监控 perplexity 或通用 benchmark 分数，一旦下降就提高文本数据比例
5. **Adaptor 设计可以稍复杂一些**：比如 2-3 层 MLP 而非单层线性，让 Adaptor 承担更多对齐负担，减轻 LLM 的适配压力

## 四、音频编码器与 Adaptor 细节

### 4.1 音频编码器

根据论文 ASR 部分的细节描述：

| 项目 | 详情 |
|------|------|
| 架构 | 0.6B 参数的 Transformer |
| 初始化来源 | Qwen3-Omni 的音频编码器 |
| 训练状态 | **全程冻结**（所有阶段都不训练） |
| 时间降采样率 | 8x（每 80ms 产生一个声学嵌入向量） |
| 输出 | 紧凑的声学嵌入序列 |

**80ms 帧率的含义**：
- 1 秒音频 → 12.5 个 embedding
- 30 秒音频 → 375 个 embedding  
- 30 分钟音频（32K 上下文窗口下）→ 22,500 个 embedding

### 4.2 Adaptor（适配器）

| 项目 | 详情 |
|------|------|
| 结构 | 线性投影层（Linear Adapter） |
| 功能 | 将声学嵌入投影到 LLM 解码器的隐空间 |
| 训练 | 第一阶段仅训练它；后续阶段一起训练 |

**关键设计选择**：Adaptor 是轻量的——论文用的是线性投影（linear projection），而不是复杂的跨模态注意力机制。这说明当编码器和解码器都足够强时，简单的线性映射就足以完成模态对齐。

### 4.3 LLM 解码器

| 项目 | 详情 |
|------|------|
| 架构类型 | MoE（Mixture of Experts）LLM |
| ASR 分支的具体信息 | 4B 参数的 Dense Transformer（从预训练文本 LLM 初始化） |
| 上下文窗口 | 原生 32K token |
| 能力 | 语义理解、上下文管理、指令跟随、多模态生成 |

### 4.4 TTS 分支的特殊设计

TTS 分支做了一个有意思的不同选择：**完全去掉了 Encoder-Adapter 模块**，纯靠 LLM backbone 建模。将音频 token 视为一种新的"语言"，语音合成被重新定义为纯粹的下一个 token 预测（NTP）任务。

这意味着：
- ASR/Realtime 方向：需要 Audio Encoder + Adaptor + LLM
- TTS 方向：只需要 LLM（text tokens → speech tokens）

### 4.5 对你项目的启示

1. **编码器可以直接用开源的**：Qwen3-Omni 的编码器是开源的，StepAudio 直接拿来冻结使用
2. **Adaptor 可以很简单**：线性投影就够了，不需要过度设计
3. **降采样率影响上下文预算**：8x 降采样使得 32K 上下文能处理约 30 分钟音频。如果你的应用需要更长音频，考虑更大的降采样率
4. **冻结编码器的好处**：训练稳定、显存占用小、不会破坏已学好的声学表征

## 五、预训练后的下游特化训练

预训练完成后，三个方向各自有专门的 SFT（监督微调）和 RLHF（人类反馈强化学习）流程。

### 5.1 ASR 方向的 SFT

| 项目 | 详情 |
|------|------|
| 数据 | 短时数据 ~100K 小时 + 长时伪标注数据 ~50K 小时 |
| 序列长度 | 32K token |
| 冻结模块 | 音频编码器冻结 |
| 训练模块 | Adaptor + LLM Decoder |
| 步数 | 10K steps |
| 学习率 | 峰值 2×10⁻⁵，cosine decay 到 1×10⁻⁶ |
| Batch size | 全局 32 |
| Warmup | 100 步 |
| 数据增强 | SpecAugment（时间和频率遮蔽） |

**短时数据特点**：
- 涵盖中文、英文、代码混合
- 覆盖专业术语领域
- 包含远场录音、高噪声等挑战性场景
- 每个样本最长 30 秒

**长时数据构造流水线**（50K 小时）：
1. VAD 分割：原始录音切成 ≤30s 片段
2. 三系统转录：每个片段用 3 个 ASR 系统独立转录
3. 格式归一化：统一格式、大小写、标点
4. ROVER 投票融合：token 级别投票，需 ≥2 个系统一致才接受
5. 质量过滤：不一致率 > 5% 的片段丢弃
6. 会话重组：通过质量的相邻片段拼接成长录音
7. LLM 精修：恢复标点、逆文本归一化、跨片段一致性（术语和实体统一）

### 5.2 TTS 方向的 SFT

**两阶段 SFT**：

**阶段 1：大规模零样本 TTS 训练**
- 使用全局指令监督（global instruction supervision）
- 学习粗粒度控制：说话人特征、说话风格、整体韵律属性
- 数据来源：Step-Audio-EditX 模型合成（利用其强大的组合编辑能力生成多样的风格和情感变化）

**阶段 2：高质量精细化训练**
- 使用同时标注了全局指令和内联指令（inline instructions）的高质量内部录音数据
- 实现句子级和片段级的细粒度控制

**TTS SFT 数据标注流程**（基于内部录音数据）：
1. Whisper-Large-v3 转录
2. Montreal Forced Aligner 获取词级时间戳
3. 按句子分割
4. 过滤对齐错误、转录不完整、时长过短的样本
5. 收集上下文元数据（对话历史或脚本上下文）
6. 提取并离散化韵律特征：F0、语速、停顿统计、频谱质心、RMS 能量、MFCC 方差、HNR
7. 将量化声学特征 + 转录 + 上下文喂给 LLM 标注
8. LLM 输出两类标注：
   - 全局控制描述：整体说话风格、韵律模式、情感状态
   - 内联表达描述：在文本中插入局部表达指令
9. ASR 交叉验证：验证分段转录的准确性

### 5.3 Realtime 方向的训练

Realtime 分支面临独特挑战：对话连贯性、人设一致性、副语言敏感性、奖励稀疏性。

**三阶段训练流水线**：

**阶段 1：Audio-Centric Mid-Training**
- 直接继承自基座预训练
- 建立音频锚定的感知和长链推理能力

**阶段 2：Progressive SFT（渐进式监督微调）**
- **对话对齐**：使用指令丰富的对话数据，训练多轮对话连贯性、处理口语化工件（语塞、中间打断），偏好口语化而非书面体
- **人设和风格控制**：从 >10,000 个人工审核的原生人设出发，通过算法裂变（fission）将正交属性（个性、语言习惯、情感边界、互动模式）组合成百万级人设矩阵，每个人设配对百万级真实场景对话
- **副语言敏感性**：使用真实口语交互数据，训练识别犹豫、轻笑、叹息、呼吸、节奏变化、降调等细微线索

**防止灾难性遗忘**：采用动态复习调度（dynamic rehearsal schedule），交互数据与通用指令数据、推理任务持续交替

**阶段 3：RLHF**
- PPO 优化 + KL 正则化
- 生成式奖励模型（Generative Reward Model）：对候选响应与参考响应进行配对打分
- 混合多轮对话和单轮提示进行训练
- 偏好比较作为主要奖励信号 + 评分准则（rubric）补充指令敏感方面

### 5.4 对你项目的启示

1. **SFT 前要有良好的预训练基础**：先完成模态对齐再做 SFT
2. **长音频需要特殊数据管线**：多系统投票 + ROVER 融合是生产可靠长音频标签的有效手段
3. **TTS 数据可以用模型合成**：不一定全靠人工录制，用强力编辑模型合成多样化数据是可行路线
4. **全双工对话需要渐进式训练**：不要一步到位，先对话对齐→再人设控制→再副语言敏感
5. **RLHF 对对话质量很关键**：SFT 只能到一定程度，对话的自然度和情感得体性需要 RLHF 进一步对齐
6. **防遗忘策略**：引入新能力时，要持续回放通用数据，防止灾难性遗忘

## 六、Speech Tokens 与词汇表扩展

### 6.1 核心概念

StepAudio 2.5 的一个关键设计是将语音也表示为离散 token，从而和文本 token 在同一个序列空间中建模。

**统一序列空间的含义**：
- 文本 token：来自原始 LLM 的 tokenizer
- Speech token：新引入的音频离散表示
- 两者在同一个解码器中被统一处理，没有架构上的分界

### 6.2 词汇表扩展的时机

词汇表扩展发生在 **阶段一（Adaptor 对齐）结束之后、阶段二（统一多模态训练）开始之前**。

这个顺序很重要：
1. 先用 ASR 数据训练 Adaptor（此时还不需要 speech tokens，因为输出是纯文本）
2. Adaptor 对齐后，LLM 已经能"听懂"音频了
3. 然后扩展词汇表，加入 speech tokens
4. 开始双向训练（既做 ASR 也做 TTS/对话等）

### 6.3 TTS 中的 Audio Token 处理

TTS 分支特别有趣——它把音频 token 视为一种新的"语言"：
- 完全去掉 Encoder-Adapter
- 纯 NTP（Next Token Prediction）
- 核心挑战变成：学习文本和音频表示空间之间的有效对齐

### 6.4 对你项目的启示

1. **离散化音频表示**：你需要一个 audio tokenizer（如 SoundStream、EnCodec、或类似方案）将连续音频转为离散 token
2. **词汇表扩展需谨慎**：扩展后需要 warmup 阶段来稳定新嵌入
3. **嵌入层和输出层需要特殊学习率**：新加入的 token 对应的嵌入向量是随机初始化的，需要更大学习率快速学习
4. **序列格式设计**：考虑好 text token 和 speech token 在序列中的组织方式（交错、拼接等）

## 八、关键设计决策总结与实践建议

### 8.1 StepAudio 2.5 的核心设计哲学

> "一旦文本和音频共享一个良好的表征空间，下游任务之间的差异就从架构迁移到了操作层面：数据、目标函数和解码约束。"

这意味着：
- **不需要为每个任务设计不同的架构**
- **重点在预训练阶段建立好共享表征**
- **后续特化靠数据设计、训练目标和解码策略的差异**

### 8.2 对全双工多模态项目的实践路线建议

如果你从零开始做一个全双工多模态模型：

**Step 1：准备工作**
- 选择一个预训练好的文本 LLM 作为基座（建议至少 7B 参数）
- 选择一个预训练好的音频编码器（Whisper、Qwen-Audio encoder 等）
- 准备或选择一个 audio tokenizer（如果需要生成音频）

**Step 2：模态对齐（最重要的第一步）**
- 只训练 Adaptor
- 用 ASR 数据（音频→文本）
- 冻结编码器和 LLM
- 数据量不需要太大（StepAudio 用了 3B tokens）
- 验证标准：模型是否能准确转录语音

**Step 3：词汇表扩展 + Warmup**
- 加入 speech tokens
- 用较大学习率训练新嵌入
- 用较小学习率保护已有模块
- 数据中混入多种任务类型

**Step 4：大规模多模态训练**
- 文本和音频 1:1 配比
- 多任务格式：ASR、TTS、翻译、交错续写、对话
- 注意 MoE router / attention 模块的学习率

**Step 5：高质量精修（Cooldown）**
- 用高质量数据
- 增加序列长度
- 引入新的数据类型（如 audio caption）

**Step 6：下游 SFT + RLHF**
- 根据你的应用场景选择方向
- 全双工对话需要渐进式 SFT + RLHF

### 8.3 常见陷阱提醒

1. ❌ 不要一开始就全参数训练——会破坏预训练好的文本能力
2. ❌ 不要只用 ASR 数据做预训练——单向数据无法建立双向接口
3. ❌ 不要忽略数据质量分级——不同阶段需要不同质量的数据
4. ❌ 不要跳过 warmup——新词汇需要稳定期
5. ❌ 不要忽略灾难性遗忘——始终混入文本数据
