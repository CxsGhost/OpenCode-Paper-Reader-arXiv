## 1. 背景、问题与贡献

论文把音频任务拆成三类：说了什么（ASR）、谁在什么时候说（带说话人和时间戳的转写），以及声音本身表达什么（环境声、音乐、副语言信息与音频问答）。3.1 在 3.0 的指令式 ASR 基础上扩展后两类任务，同时保留 30 种语言、16 种中国方言、历史上下文、分层热词和原生转写润色。

主要贡献是把不同输出结构纳入音频条件下的自回归生成，并通过多阶段训练整合任务能力。训练上最值得关注的是：大规模 ASR 对齐之后，显式加入非 ASR 监督；为说话人 token 和时间戳调整训练目标；用任务指标进行 RL；最后以任务路由的多教师在线蒸馏整合能力。作者没有把单纯扩大 ASR 数据视为通用音频理解的充分条件。（原文 §1–3）

## 2. 模型与任务边界

架构为音频编码器 → adapter → Qwen MoE 解码器。辅助 CTC 分支提供初步转写、热词和长音频上下文处理所需线索，并非先把音频完全压成文本再做所有任务。核心条件生成式为：

\[
H=A(E(x)),\qquad p_\theta(y\mid x,q,c)=\prod_{t=1}^{T}p_\theta(y_t\mid y_{<t},H,q,c).
\]

其中 \(x\) 是音频，\(E,A\) 分别是编码器和 adapter，\(q\) 是任务指令，\(c\) 是历史或热词等文本条件，\(y\) 是目标输出。相同生成范式可输出转写、说话人/时间结构或音频答案；这描述架构与监督接口，并不单独证明模型已学会每种声学属性。（§2.1）

| 型号（省略共同前缀） | 主要场景 | 说话人/时间戳转写 | 通用音频理解 | 原生润色 |
|---|---|---|---|---|
| Flash-Filetrans | 异步文件转写 | 不支持 | 不支持 | 不支持 |
| Flash-Streaming | 实时转写 | 不支持 | 不支持 | 不支持 |
| Flash-Message | 交互语音输入 | 不支持 | 不支持 | 支持 |
| Flash | 非流式转写 | 支持 | 不支持 | 支持 |
| Next | 非流式转写与分析 | 支持 | 支持 | 支持 |

表格严格按论文表1；所有型号都支持 ASR、上下文和热词。实验中的“Qwen-Audio-3.1-ASR”指非流式 Flash；音频理解成绩来自 Next，不能转移到 Streaming 或 Message。流式采用增量显示、句末完整上下文刷新，部分结果会修订。（§2.4、§4）

## 3. 训练链路：本文的阅读重点

| 阶段 | 数据与监督 | 参数更新范围 |
|---|---|---|
| 编码器预训练 | BEST-RQ 掩码离散目标预测 → AED 转写监督；两阶段合计“数千万小时” | 训练编码器；兼容 Transformer 层从 Qwen3 初始化，非流式改双向注意力；AED 解码器随后丢弃 |
| Audio LLM 预训练 | 约 2000 万小时多语种音频，以 ASR、交错文本—音频为主；文本 CE | 编码器冻结，adapter 与 MoE LLM 联合训练 |
| Cooldown | 约 100 万小时高质量数据，语言/方言再平衡；加入音频理解、说话人、语音问答/对话 | 编码器冻结，更新 adapter 与 LLM |
| SFT | 指令式 ASR + 说话人转写 + 按型号加入理解任务 | 更新编码器与 adapter；LLM 基座冻结、解码器用 LoRA |
| RL | 困难 ASR 与说话人转写；GRPO 优化任务指标 | 未逐模块披露冻结范围 |
| 多教师 OPD | ASR、说话人、音频理解、文本/对话按任务路由教师 | 教师冻结；学生具体模块更新范围未完整披露 |

这里有三点对训练工作尤其重要。首先，cooldown 用 VibeVoice 回识别，删除与原转写 WER > 0.3 的样本，属于一致性筛选，**没有把参考标签替换成 VibeVoice 输出**。其次，非 ASR 能力有显式监督：Next 的 SFT 包含语音/环境声/音乐 caption、带时间区间的定位、开放式及选择式问答。最后，SFT 重新开放声学编码器训练，而非始终依赖固定声学表征。（§3.1–3.4）

识别增强的数据工程包括：领域实体挖掘 → 基于事实生成含实体短句 → CosyVoice3 合成/补真人录音 → 回识别过滤；真实会话历史只取前文，合成历史覆盖正确、冲突、噪声和空上下文；P0/P1 分层热词同时训练。润色则以“原音频 + 润色后目标文本”直接监督，并用填充词、重复、自我纠正的合成语音补充。因此，训练目标文本会直接决定输出是逐字转写还是清理后的表达。（§3.4.1）

说话人目标序列为 `[SPK|start-end]text`，同一录音内保持标签一致，允许时间区间重叠。训练有两个具体调整：**仅将 speaker-ID 数字 token 的 CE 权重设为 10，其他 token 仍为 1；把原始 1 ms 精度时间戳量化到 80 ms 网格，与编码器及 adapter 的 12.5 Hz 表示对齐。** 动机分别是说话人数字仅占 2.90% token、1.97% 未加权损失，以及监督时间精度与表征分辨率不匹配。作者称收敛和 DER/cpWER 改善，但没有给出完整定量消融。（§3.4.2，图5–6）

## 4. 后训练：RL 与多教师蒸馏各负责什么

RL 使用精选困难样本：多识别器分歧、超过 20 秒的长句、幻觉与真实长重复、实体/热词，并混入普通 ASR 防遗忘。GRPO 对同输入的一组候选进行组内奖励标准化，再用裁剪策略目标和 KL 正则更新；没有单独训练 value 网络。ASR 奖励包括 \(1-\mathrm{WER}\)、关键词准确性/召回、热词和历史实体命中、误插入及幻觉惩罚；说话人转写奖励使用 DER、cpWER、tcpWER，分别约束说话活动/混淆、说话人归属文字和时间一致性。各奖励按任务路由，具体组合权重未公开，正文没有给出独立 AU 奖励。（§3.5）

多教师 OPD 随后让学生先生成回答，教师在相同学生前缀上打分，优化 token 级 \(k_3=\rho-\log\rho-1\)，其中 \(\rho=p_{\mathrm{teacher}}/p_{\mathrm{student}}\)。在当前学生 on-policy 采样条件下，其期望估计 \(D_{\mathrm{KL}}(\pi_{\mathrm{student}}\Vert p_{\mathrm{teacher}})\)。ASR、说话人、音频理解分别路由专门教师，文本/对话路由 Qwen3.5；目的在于整合专长并保留语言能力。它不是把多位教师的概率简单平均，也不是仅用教师固定答案做 SFT。（§3.6）

两阶段通过 FunVerl 的异步流水线运行：Ray 编排音频预处理、vLLM rollout、任务奖励/教师评分和 Megatron 更新，使用队列、策略版本限制及 NCCL 权重同步。未披露各阶段 batch、学习率、LoRA rank、rollout 组大小、KL 系数、教师规模和训练成本；这些缺项限制了配方复现。

中文/英文基线分为公开来源的 Panel A 和作者统一 API 流程的 Panel B，应主要在 Panel B 内直接比较；3.0 行来自历史报告。AISHELL-2 为 test-ios；Panel B 的 WeNetSpeech-net 用修订参考文本。说话人评测把音频标准化为约 4 分钟块，不能据此证明整场长会议的身份一致性；VibeVoice、SoulX 的星号行另取自其技术报告。Next 在 MLC-SLM 和 MagicData-RAMC 的 cpWER 还略逊于 Flash，不能说联合任务必然互相促进。

应用评测包括内部方言 ASR 宏平均 CER 10.38%（16 方言），以及 P0 热词召回 97.95%–99.46%；这类内部结果不能替代公开可复现对照。长音频上下文主要展示纠错案例，未给总体错误率消融。润色把内部五分制可读性从 2.53 提到 3.44，同时忠实度从逐字稿的 3.51 降至 3.44，存在取舍。（§5.2–5.6）

Message 首字延迟 100 ms，对比 Doubao 570 ms；条件是 Qwen 自部署 H100、对方 API、10 路并发，且假设网络延迟相当。它衡量中间转写显示，不是音频理解延迟，也不是语音对话端到端响应。（§5.7，表6）

## 6. 结论、局限与训练视角评价

作者展示了从 ASR 扩展到结构化转写及音频理解的工程路线。对训练工作，最有价值的内容是**数据混合如何改变监督目标、阶段间怎样切换可训练模块，以及如何把少量关键结构 token 和时间分辨率纳入优化设计**。领域实体合成、冲突历史训练、真实长重复与幻觉样本并存，也比笼统的“增加数据”更有操作意义。

但报告仍是路线说明，尚不足以作为完整复现配方：没有模型总/激活参数、详细结构超参数、SFT/RL/OPD 数据规模与比例、LoRA 配置、训练步数及算力预算，也缺少逐阶段、数据混合和教师选择的系统消融。数千万小时编码器数据与后续 2000 万/100 万小时的去重关系未给出，不能相加成独立数据量。报告没有明确的独立未来工作章节，训练方面仍值得补齐的验证见训练专题。

个人建议优先借鉴三项：先按输出类别审计 token 数量和 CE 份额，再决定是否重加权；让时间目标与实际音频表示分辨率对齐；需要非词汇声学能力时，加入对应标签与独立评测。MELD 等成绩是指定任务下的输出证据，不能直接证明隐藏表征已充分保留情绪，更不能证明这些信息能稳定传递到其他下游模块。若采用多教师 OPD，还应保留相同教师/数据预算的普通蒸馏基线。（具体实验建议见 [训练专题 §7](training_analysis.md#7-面向自身训练工作的优先实验建议)）
