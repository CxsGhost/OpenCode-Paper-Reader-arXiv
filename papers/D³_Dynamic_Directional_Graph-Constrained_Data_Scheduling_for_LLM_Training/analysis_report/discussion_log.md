**用户问：** 帮我读这篇论文：https://arxiv.org/abs/2605.31164

**回答：**

本次阅读的是 **D³: Dynamic Directional Graph-Constrained Data Scheduling for LLM Training**，版本为 **arXiv:2605.31164v1**（2026-05-29）。已下载固定版本的 LaTeX，阅读全文、附录和算法，并核对消融图。完整分析见 [summary.md](summary.md)，独立公式推导与反例见 [technical_audit.md](technical_audit.md)。下列实验均为作者报告，没有独立训练复现。

论文研究“相同数据按什么顺序训练更有效”。它在当前参数处，估计先沿批次 $i$ 的梯度更新，会怎样改变批次 $j$ 的损失：

$$
\mathcal I_{i\to j}=\ell_j(\theta-\gamma g_i)-\ell_j(\theta)
\approx-\gamma g_j^\top g_i+\frac{\gamma^2}{2}g_i^\top H_jg_i.
$$

其中 $g_i$ 是批次梯度，$H_j$ 是批次损失 Hessian，$\gamma$ 是前瞻步长。负值意味着损失下降。一阶内积对称，二阶曲率一般不对称，因此作者用后者建立有向影响图，再按“违反排序偏好的总权重最小”求顺序。求解器先按优势矩阵行和排序，再接受能降低代价的随机交换；实际计算限定在候选窗口中，采用梯度投影与 Hessian 对角近似。来源：§3.2–§3.5。

作者报告的主要结果如下。预训练综合分为五项常识任务的平均 accuracy，SFT 综合分为四项数学与代码任务百分数的平均，二者不可跨行直接比较。

| 场景 | 对照 | D³ |
|---|---|---|
| 355M GPT / SlimPajama / 100B tokens | Dynamic Loss：PPL 3.10，平均分 41.26 | PPL 2.97，平均分 42.56 |
| 1.1B Llama / Pile / 100B tokens | 最佳基线 PPL 2.64；最佳平均分 49.94（两项来自不同方法） | PPL 2.53，平均分 51.88 |
| Llama-3-8B SFT | DSL 单域参考平均 46.5 | 平均 49.6 |

来源：正文表 1–2、附录 D.2 表 7。355M 的 PPL 相对 Dynamic Loss 下降约 4.2%；SFT 平均分比 DSL 高 3.1 个百分点。提升并非每个任务都成立，例如 GPT 实验的 PIQA 低于 Dynamic Loss。

成本需要单独看：表 3 中 Random 为 5.53 GPU 小时，RSR 为 10.45 GPU 小时，增加约 89%。论文没有给出相同 GPU 时间或 FLOPs 下的效果对照，也没有达到同一目标 PPL 的耗时，因而尚不能断言训练更省算力。

本次核查发现两个更实质的问题：

1. **高效公式会退化为曲率排序。** 正文和附录最终写成 $\widehat{\mathcal I}_{i\to j}=-\gamma\tilde g_j^\top\tilde g_i+(\gamma^2/2)\lambda_j$。代入 $S_{ij}=\mathcal I_{j\to i}-\mathcal I_{i\to j}$ 后，内积抵消，得到 $S_{ij}=(\gamma^2/2)(\lambda_i-\lambda_j)$。因此按行和排序已满足全部严格偏好，代价为零，没有有向环供 RSR 处理；这与求解器消融及投影维度的机制解释存在冲突。结论来自公式推导与四批次穷举，不代表已经核对了作者运行代码。
2. **理论引理在明示条件下存在反例。** 取一维线性回归 $(x_a,y_a)=(1,1)$、$(x_b,y_b)=(2,3)$、$\theta_0=0$，总损失为 $[(1-\theta)^2+(3-2\theta)^2]/4$。原文 SGD 的两种顺序给出 $D_{ab}=7\eta^2-35\eta^3+25\eta^4$，原引理却给出 $32\eta^2+O(\eta^3)$。二阶系数不同，需要修正公式或补充条件。详见技术核查文档。

2026-11-20 实时查看[作者代码仓库](https://github.com/xuyj233/D3)，根目录仅有 README，说明工具包仍在准备，无法核对实际实现与公式的差异。论文还缺少完整 few-shot 协议、SFT 配方、多种子统计和大规模投影的工程说明。

我的判断是：动态数据排序与当前优化状态相结合的视角值得借鉴，作者报告的效果值得复核；但目前公开材料对图机制、理论保证和算力效率的支持都不充分。优先复现随机排序、直接曲率分数排序和完整交叉曲率排序，并统一计算预算，才能判断复杂图调度是否带来额外收益。
