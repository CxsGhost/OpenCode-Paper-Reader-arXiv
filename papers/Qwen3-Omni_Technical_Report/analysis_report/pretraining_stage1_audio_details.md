## 一、预训练 Stage-1：编码器对齐阶段 (Encoder Alignment Stage)

### 1.1 阶段目标

在预训练的第一阶段，主要目标是**将音频编码器和视觉编码器与冻结的 LLM 进行对齐**，使得编码器提取的特征能够被 LLM 理解并用于后续的多模态推理。

### 1.2 初始化策略

| 模块 | 初始化来源 | 参数规模 |
|------|-----------|---------|
| LLM (Thinker) | Qwen3 预训练权重 | 30B-A3B |
| 视觉编码器 | Qwen3-VL (基于 SigLIP2-So400M) | 540M |
| 音频编码器 | AuT (Audio Transformer) | 650M |

### 1.3 训练策略：两阶段序贯训练

Stage-1 采用**冻结 LLM + 分别训练两个编码器**的策略。两个编码器（视觉、音频）各自独立进行如下两个子阶段的训练：

#### 子阶段 1：仅训练 Adapter
- **冻结模块**：LLM + 音频编码器 + 视觉编码器
- **训练模块**：音频 Adapter + 视觉 Adapter
- **目标**：学习将编码器输出的特征映射到 LLM 的输入空间，为编码器建立与 LLM 之间的"桥梁"

#### 子阶段 2：训练 Encoder
- **冻结模块**：LLM（Adapter 大概率也冻结，见下方分析）
- **训练模块**：音频编码器 + 视觉编码器
- **目标**：在 Adapter 已建立好映射的基础上，优化编码器本身的特征提取能力

> **注**：论文原文表述为 "initially focusing on training their respective adapters before training the encoders"，仅说"先训 adapter 再训 encoder"，并未明确写 adapter 在子阶段 2 是否继续参与训练。但结合下文"放弃联合训练"的论述，更合理的解读是子阶段 2 中 adapter 冻结、仅训练 encoder，从而实现 adapter 训练与 encoder 训练的完全解耦。

### 1.4 与 Qwen2.5 系列的关键差异

Qwen2.5-VL 和 Qwen2.5-Omni 在对齐阶段的做法是：**冻结 LLM，让编码器和 Adapter 从一开始就联合训练**（没有先单独训 adapter 的热身阶段）。

Qwen3-Omni **放弃**了这种联合训练方式，改为上述序贯训练。

**原因**：
- 在 LLM 冻结的情况下，如果编码器和 Adapter **从一开始就同时训练**，编码器可能会**补偿冻结 LLM 的局限性**
- 这会导致编码器学到的表示过度依赖当前 LLM 的状态，**损害其感知能力的泛化性**
- 通过先单独训好 Adapter（建立映射通道），再单独训 Encoder（优化感知特征），确保编码器学到的是更通用的特征表示，而非针对冻结 LLM 的补偿性表示

### 1.5 训练数据

Stage-1 使用**大规模的音频-文本对和图像-文本对**：
- **音频-文本对**：用于训练音频编码器和 Adapter
- **图像-文本对**：用于训练视觉编码器和 Adapter

具体数据规模未在论文中明确披露，但从 AuT 的训练数据可以推断音频部分使用了大规模监督数据。

## 二、AuT (Audio Transformer) 音频编码器详解

### 2.1 架构设计

AuT 是一个**注意力编码器-解码器架构**（Attention Encoder-Decoder），采用自回归训练方式。

#### 核心设计特点：

1. **从头训练 (Trained from Scratch)**
   - 不同于 Qwen2.5-Omni 使用的 Whisper 编码器
   - AuT 完全从零开始训练，专门为 Qwen3-Omni 定制

2. **输入处理**
   - 音频重采样至 **16 kHz**
   - 转换为 **128 通道 Mel 频谱图**
   - 窗口长度：25ms，跳跃长度：10ms

3. **下采样机制**
   - 使用 **Conv2D 块**在注意力层之前进行 8 倍下采样
   - 将 token 率降至 **12.5 Hz**
   - 每个音频帧对应约 **80ms** 的原始音频信号

4. **参数规模**
   - 编码器约 **0.6B (600M)** 参数

### 2.2 训练数据配置

AuT 在 **2000 万小时有监督音频数据**上训练，数据组成如下：

| 数据类型 | 占比 | 说明 |
|---------|------|------|
| 中英文伪标签 ASR 数据 | 80% | 使用其他 ASR 模型生成的伪标签进行训练 |
| 多语言 ASR 数据 | 10% | 覆盖中英之外的其他语言 |
| 音频理解数据 | 10% | 包括音频分类、事件检测、音乐理解等任务 |

**训练任务**：
- **语音识别 (ASR)**：主要任务，占 90%
- **音频理解**：包括音频分类、事件检测、音乐理解等，占 10%

### 2.3 动态注意力窗口

为了平衡**实时预填充缓存效率**和**离线任务性能**，AuT 使用了 **Flash Attention + 动态注意力窗口**：

- **窗口大小范围**：1 秒至 8 秒
- **覆盖的注意力查询模式**：短时依赖（1秒）到长时依赖（8秒）
- **作用**：
  - 短窗口（1-2秒）：适用于实时流式场景，减少延迟
  - 长窗口（6-8秒）：适用于离线音频理解任务，提升性能

### 2.4 与 Whisper 的对比

| 特性 | AuT | Whisper (Qwen2.5-Omni) |
|------|-----|------------------------|
| 训练方式 | 从头训练 | 预训练模型微调 |
| 训练数据 | 2000万小时监督数据 | 68万小时弱监督数据 |
| Token 率 | 12.5 Hz | 50 Hz (需额外下采样) |
| 注意力机制 | 动态窗口 (1-8秒) | 固定全局注意力 |
| 实时性 | 原生支持流式 | 需额外改造 |
| 音频理解任务 | 训练数据中包含 10% | 主要针对 ASR 优化 |

### 2.5 输出特征

- **Token 率**：12.5 Hz（每秒 12.5 个 token）
- **时间分辨率**：每个 token 对应约 80ms 音频
- **特征维度**：与 LLM 输入维度对齐（通过 Adapter 映射）

## 三、音频输入流程（从原始波形到 LLM 输入）

### 3.1 完整流程

```
原始音频波形 (任意采样率)
    ↓
重采样至 16 kHz
    ↓
转换为 128 通道 Mel 频谱图 (25ms 窗口, 10ms 跳跃)
    ↓
Conv2D 块进行 8 倍下采样
    ↓
AuT Encoder 提取特征 (12.5 Hz token 率)
    ↓
音频 Adapter 映射到 LLM 输入空间
    ↓
进入 Thinker (LLM) 进行多模态推理
```

### 3.2 时间对齐机制 (TM-RoPE)

Qwen3-Omni 使用 **Time-aligned Multimodal RoPE (TM-RoPE)** 进行音视频时间对齐：

- **RoPE 分解**：将旋转位置编码分解为三个维度
  - 时间维度：24 个旋转角度
  - 高度维度：20 个旋转角度
  - 宽度维度：20 个旋转角度

- **音频位置编码**：
  - 每 80ms 分配一个时间 ID
  - 高度和宽度 ID 保持一致（因为音频是一维信号）

- **音视频对齐**：
  - 视频帧根据其时间戳动态分配时间 ID
  - 与音频使用相同的 80ms 时间分辨率
  - **直接基于时间 ID 对齐**，不再使用 Qwen2.5-Omni 的 2 秒固定分块

## 四、Stage-2 和 Stage-3 中的音频训练

### 4.1 Stage-2: General Stage (通用阶段)

- **数据规模**：约 2 万亿 tokens
  - 文本：0.57T
  - **音频：0.77T** (占比最大的单模态数据之一)
  - 图像：0.82T
  - 视频：0.05T
  - 视频-音频：0.05T

- **训练策略**：
  - **解冻所有参数**：LLM + 所有编码器 + 所有 Adapter
  - 引入更多样化的多模态数据和任务
  - 增强模型在听觉、视觉、文本和音视频信息上的理解和交互能力

### 4.2 Stage-3: Long Context Stage (长上下文阶段)

- **序列长度提升**：从 8,192 提升至 32,768 tokens
- **数据调整**：增加长音频和长视频的比例
- **音频能力提升**：
  - 支持**超过 40 分钟**的音频理解
  - 改善长音频的上下文建模能力

## 五、音频后训练 (Post-training) - Talker 的四阶段训练

虽然 Thinker (理解模块) 的后训练主要关注文本和多模态理解，但 **Talker (语音生成模块)** 有专门的四阶段后训练流程：

### 5.1 Stage 1: 大规模语音数据预训练

- **数据规模**：数亿条语音数据，带有多模态上下文
- **目标**：建立从多模态表示到语音的**单调映射** (monotonic mapping)
- **学习内容**：
  - 语音的基本生成能力
  - 韵律、情感、口音等属性的上下文适应性

### 5.2 Stage 2: 高质量数据持续预训练 + 长上下文训练

- **目标 1**：减少幻觉
  - 使用高质量数据缓解 Stage 1 中噪声数据导致的幻觉问题
  
- **目标 2**：增强长上下文能力
  - 提升 Talker 处理长输入和生成上下文相关语音响应的能力

### 5.3 Stage 3: DPO 优化

- **方法**：Direct Preference Optimization (DPO)
- **数据**：多语言语音偏好对
- **目标**：
  - 提升多语言语音生成的泛化能力
  - 增强系统稳定性

### 5.4 Stage 4: 说话人微调

- **目标**：使 Talker 能够采用特定音色
- **优化维度**：
  - **自然度** (Naturalness)
  - **表现力** (Expressiveness)
  - **可控性** (Controllability)

## 六、音频能力的关键指标

### 6.1 实时性能

| 指标 | 数值 | 说明 |
|------|------|------|
| 端到端首包延迟 (纯音频) | 234 ms | 业界领先水平 |
| 端到端首包延迟 (音视频) | 547 ms | 包含视觉编码器处理时间 |
| RTF (Real Time Factor, 6并发) | 0.66 | <1 表示实时生成无中断 |

### 6.2 音频理解性能

- **36 个音频/音视频基准中**：
  - 32 个达到**开源 SOTA**
  - 22 个达到**总体 SOTA** (超越闭源模型)

- **ASR 性能**：
  - Librispeech、Wenetspeech、Fleurs、CommonVoice 达到最优
  - 支持 **19 种语言**的语音理解

- **VoiceBench**：
  - Thinking 版本：89.5 分
  - 接近 Gemini-2.5-Pro (89.6 分)

- **音频推理**：
  - MMAU/MMSU 基准超越 Gemini-2.5-Pro 和 GPT-4o-Audio

- **音乐理解**：
  - RUL-MuchoMusic 达 SOTA
  - 显著超越 Gemini-2.5-Pro 和 GPT-4o-Audio

### 6.3 语音生成性能

- **零样本 TTS**：
  - SEED test-en WER: 1.39% (最优)
  - SEED test-zh WER: 1.07%

- **多语言生成**：
  - 支持 **10 种语言**
  - 在中/英/法等语言显著超越 MiniMax-Speech 和 ElevenLabs

- **跨语言生成**：
  - any-to-en 和 any-to-ko 超越 CosyVoice3

## 七、核心技术创新总结

### 7.1 编码器对齐阶段 (Stage-1) 的创新

1. **序贯训练策略**：先单独训练 Adapter，再单独训练 Encoder（解耦训练）
   - 放弃 Qwen2.5 的 encoder+adapter 联合训练方式
   - 避免编码器过度补偿冻结 LLM 的局限性
   - 提升编码器感知能力的泛化性

2. **从头训练 AuT**：
   - 2000 万小时监督数据，远超 Whisper 的 68 万小时
   - 原生支持 12.5 Hz token 率，无需额外下采样
   - 动态注意力窗口平衡实时性和离线性能

### 7.2 音频处理的关键优势

1. **极低的 Token 率**：12.5 Hz
   - 每秒仅需 12.5 个 token，显著降低计算开销
   - 每个 token 对应 80ms 音频，足够捕捉语音细节

2. **动态时间对齐 (TM-RoPE)**：
   - 直接使用时间 ID 对齐音视频
   - 支持任意长度的流式输入

3. **全模态无降智**：
   - 音频编码器的训练不会损害文本和视觉能力
   - 音频数据甚至能提升视觉任务的性能 (MMMU、OCR)

## 九、个人评价

### 9.1 Stage-1 设计的亮点

1. **序贯训练策略的合理性**：
   - 将 adapter 训练和 encoder 训练完全解耦，避免了编码器与 LLM 之间的"共同适应"问题
   - 先让 adapter 建立映射通道，再让 encoder 在稳定通道上优化感知特征
   - 确保编码器学到的是泛化的特征，而非针对特定冻结 LLM 的补偿性表示

2. **从头训练 AuT 的必要性**：
   - Whisper 虽然强大，但其 50 Hz token 率对实时场景不友好
   - AuT 的 12.5 Hz 设计从根本上降低了后续模块的计算负担
   - 2000 万小时的训练数据确保了感知能力的全面性

### 9.2 潜在的局限性

1. **Stage-1 细节披露不足**：
   - Adapter 和 Encoder 的训练轮数、学习率等超参数未披露
   - 无法完全复现训练流程

2. **动态注意力窗口的实现细节缺失**：
   - 如何在训练和推理时动态调整窗口大小？
   - 不同窗口大小的数据采样比例如何设计？

3. **计算成本**：
   - 2000 万小时音频的训练成本极高
   - 对于研究社区，复现难度较大

### 9.3 总体评价

Qwen3-Omni 的 Stage-1 设计体现了**工程与学术的平衡**：
- 序贯训练策略基于对多模态学习机制的深刻理解
- AuT 的从头训练是为了实现极致的实时性能
- 动态注意力窗口兼顾了不同应用场景的需求

这套方案为多模态大模型的预训练提供了重要的参考范式，尤其是**如何在不损害其他模态的前提下集成新模态**的问题上，给出了一个实证有效的解决方案。
