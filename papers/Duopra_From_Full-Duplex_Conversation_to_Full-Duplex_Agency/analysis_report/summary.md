# Duopra：从全双工对话到全双工任务执行

- **完整标题**：Duopra: From Full-Duplex Conversation to Full-Duplex Agency
- **论文版本**：[arXiv:2611.25773v1](https://arxiv.org/abs/2611.25773v1)，2026-11-19 提交；本报告于 2026-11-23 阅读。
- **作者与机构**：Chiyu Chen、Pengzhou Cheng 等；上海交通大学、腾讯、上海大学、布里斯托大学。
- **阅读依据**：v1 LaTeX 正文、附录 A–G、所引用的表格与图注。以下实验数值均为作者报告，本次未独立训练或运行模型评测。

## 1. 背景与动机

全双工语音模型已能边听边说、处理停顿和打断，但“会接话”不代表“会办事”。在前端负责对话、后端负责工具执行的架构中，前端仍须判断信息是否充分、保留用户最后一次更正、发出完整请求；后端无法执行一个没有收到的任务。

作者发现，在其流式评测管线中，RV-Audio + Harness 只有 11.0% 的会话发起后端委托，最终 Pass@1 为 4.7%。保持委托行为不变，即使后端执行完美，成功率也不会超过 11.0%。这是特定配置中的启动瓶颈，不能推广为所有前后端架构的上限。Duopra 因此把对话控制和任务行动一起训练，而非仅替换更强的后端。（正文 §1、§3、§5.3）

## 2. 问题定义与核心创新

每个 1 秒音频单元中，因果策略输出 \(y_t=(m_t,w_t,a_t)\)：\(m_t\) 表示听/说状态，\(w_t\) 为公开语音文本，\(a_t\) 为不朗读的私有动作。策略仅使用当前及历史音频、已返回的观察和过去输出：

\[
\pi_\theta(y_t\mid x_{\le t},e_{\le t},y_{<t}).
\]

这里 \(e_t\) 包含工具 schema 和执行结果。必要参数必须来自用户最后有效的表述、先前工具结果或明确的上下文默认值；缺必要参数才追问，缺可选参数则用默认值。比如“买两台笔记本，改成一台平板”，必须搜索平板，并用搜索返回的 ID 加购一台。（§3，式 1）

核心设计是把后端也注册为 `query(task)` 工具：自然语言参数需包含最新值、所需步骤、条件和依赖关系。前端的三种工具权限是 **Direct**（仅领域工具）、**Backend**（仅后端工具）、**Both**（两者均可）。所有调用共用私有 `<delegate>` JSON 接口，结果通过 `<backend>` 注入；`select` 可检索 schema，`call` 执行调用。动作仍留在 thinker 自回归历史中，但 talker 只接收公开语音位置，避免把工具 JSON 朗读出来。（§4.1；附录 C）

贡献主要在于把“何时行动、参数是否忠实、能否执行完”变为可训练和可诊断的问题，并处理训练 thinker 后出现的语音条件漂移；全双工和工具调用本身并非本文首次提出。

## 3. 方法与训练

### 3.1 基座与协议 SFT

基座为 **9B RV-Audio**：thinker 隐藏维度 4096；talker 为 20 层、768 维、12 头；音频使用 s3tokenizer，词表 6,562，Token2wav 输出 24 kHz 语音。连接 thinker 与 talker 的 projector 为 `4096 → 768 → 768` MLP，共 3,737,088 参数。（附录 A；`tables/tabA_hparams.tex`）

Stage 1 使用 **12,800 会话**，约 70% 中文、30% 英文；60% 任务演示、40% 能力保留对话。目标覆盖听说控制、schema 检索、澄清、JSON 调用、结果播报等。72 个工具定义分为训练 40、验证 16、测试 16；会话验证/测试集分别为 4,711/4,195。

损失是 thinker 目标输出 token 的交叉熵：公开文本、私有动作、双工控制 token 等权；先按会话目标 token 数归一化，再平均会话。用户音频、工具观察和宿主强制插入的边界只作条件，不计损失。**更新 thinker 全部 transformer 层和末端归一化**；冻结词嵌入、LM head、音频编码器、talker（含 projector）和 vocoder。AdamW，峰值学习率 \(2\times10^{-6}\)，5% warm-up，最低 \(2\times10^{-7}\)，batch 32，400 次更新；产物为 Duopra-SFT。（§4.2；附录 A.2、B.2）

### 3.2 全双工 RL：从发起调用到完成任务

- **Stage 2a → Duopra-RL1**：7,908 个任务，70.5% 中文；训练直接调用、澄清、纠正/取消、打断和用户附和处理等，使用 52 个领域工具。
- **Stage 2b → Duopra-RL**：新增 1,087 个训练任务（681 英文、406 中文）、152 个验证任务，涵盖单步、多步/依赖/条件、纠正、信息充分性、失败恢复。新任务与 2a 回放按 45:55 采样。32 类工具功能通过 84 个目录形成 2,688 个 schema，目录按 64/20 划分训练/验证；训练任务中 54% 工具全可见、29% 部分仅后端可见、17% 全部仅后端可见。（附录 B；`tables/tabA_datacard.tex`）

每个任务使用相同的预合成用户音频采样 **8 条完整流式轨迹**，包括固定时刻的后续发言；执行模拟工具，2b 的后端为冻结的 **Qwen3.8-27B**。运行日志检查调用、参数和时序，LLM judge 对公开回答提供逐目标证据，程序再核验引用观察、数字和时间先后。不能将尚未返回的结果当作已知事实。（§4.3；附录 C、D）

2a 使用按任务族组合的细粒度奖励：充分信息下请求结束后 3 秒单元内行动得 +0.1，沿用被更正的值每项 −0.6，打断后须在 2 单元内停说；还检查必要澄清、结果依据和继续说话行为。2b 新任务改用**完整请求结果分档**：完整执行且回答有依据，在 ≤3、(3,8]、>8 单元行动分别得 1.2、1.1、0.9；诚实报告部分完成得 \(0.1+0.15c\)，\(c\) 为正确完成步骤比例；捏造结果得 −0.95。重复执行罚 −0.2，可见单步工具仍成功委托额外扣 0.05。2a 回放仍按原奖励计分。时间锚定输入音频，不能把这些门限等同于端到端服务延迟。

优化采用 **Dr. GRPO**，只训练 thinker attention/MLP 的 LoRA（\(r=\alpha=32\)）：

\[
A_i=r_i-\frac{1}{|I|}\sum_{k\in I}r_k,\qquad
J=\mathbb E\!\left[\frac{1}{|I|L}\sum_{i\in I}\sum_{j\in\mathcal M(\tau_i)}
\big\{\min(\rho_{ij}A_i,\operatorname{clip}(\rho_{ij},1-\epsilon,1+\epsilon)A_i)-\beta K_{ij}\big\}\right].
\]

\(I\) 为成功打分的轨迹，\(\rho\) 为当前/采样策略的 token 概率比；优势只减组均值，不除奖励标准差；\(L=2048\) 为固定归一化常数，\(\epsilon=0.2\)，\(\beta=0.01\)。KL 参考为 Duopra-SFT，采用 k3 估计；至少 4/8 轨迹有效且奖励方差非零才保留组。每次更新 32 组，Adam，学习率从 \(3\times10^{-6}\) 余弦降至 \(10^{-6}\)。后端意外失败在前端请求充分且忠实等条件下过滤，脚本设计的恢复失败则保留训练。（式 4；附录 A、D）

### 3.3 Projector 修复：适配更新后的隐藏状态

talker 条件为文本 embedding 加上归一化的 projector 输出。thinker 更新后，即使文本相同，隐藏状态分布改变也可能损害发音。作者对同一个流前缀分别运行原始 thinker 和 RL thinker，缓存公开语音位置的成对状态，用原始 projector 作用于原始状态的方向作为目标：

\[
u_j^0=\operatorname{L2norm}(P_{\phi_0}(h_j^{orig})),\quad
u_j^\phi=\operatorname{L2norm}(P_\phi(h_j^{RL})),
\]
\[
\mathcal L_{proj}=\mathbb E_j[1-\cos(u_j^\phi,u_j^0)]
+0.01\|\phi-\phi_0\|_2^2.
\]

余弦项对齐投影方向，L2-SP 将参数锚定原始权重；**只训练 projector，冻结 thinker、talker 主体、文本 embedding 和 vocoder**，并非重新训练整个 TTS。训练/验证/测试缓存为 931/100/210 会话；训练含 35,154 对 token 状态，450 次更新、每 batch 8,192 token、学习率 \(10^{-4}\)。最终 **Duopra = Duopra-RL thinker + 修复 projector**，所有标注 Duopra 的评测均采用该组合。（§4.4，式 5；附录 A.4、E.1）

## 4. 实验设计与主要结果

FDB v3 包含 12 位说话人的 **100 条不流畅英语录音、12 个模拟 API**；66/18/16 条请求需 1/2/3 次调用。每配置 3 个解码种子，共 300 会话，参数与回答由 Qwen3.8-27B 打分。**Pass@1 只要求实际执行的工具及参数精确覆盖所有 gold 调用，且无多余调用**；用户纠正前已执行的过时调用也会导致失败。回答依据与质量另计，训练中的完整成功奖励比该 Pass@1 定义更广。（§5.1；附录 E.2）

| 模型/权限 | 推理后端 | Call：有领域调用的会话% | Pass\|call% | Pass@1% |
|---|---|---:|---:|---:|
| RV-Audio + Harness | Qwen3-8B | 10.3 | 45.2 | 4.7 |
| Duopra-SFT / Direct | 无 | 44.7 | 58.2 | 26.0 |
| Duopra-RL1 / Direct | 无 | 56.3 | 47.3 | 26.7 |
| Duopra / Direct | 无 | 81.3 | 58.6 | 47.7 |
| Duopra / Backend | Qwen3-8B | 86.7 | 51.5 | 44.7 |
| Duopra / Backend | DeepSeek-V4.1-Flash | 77.0 | 64.1 | 49.3 |

数值来自主表 `tables/tab1_main.tex`，均为作者同一流式管线结果；训练后端 Qwen3.8-27B 与评测后端 Qwen3-8B 不能混同。DuplexOmni 在作者相同后端/工具管线中为 17.0%。外部商业系统采用其他评测与 judge，不能与本表拼成严格排名；RV-Audio 的已发表离线 42.0% 也不是流式 Harness 的 4.7%。

这些结果支持三点：

1. **前端启动是本次基线的主要瓶颈。** 恒等式 \(P(pass)=P(call)P(pass\mid call)\) 将覆盖率与条件成功分开。基线发起委托有 33/300 会话（11.0%），真正执行领域调用为 31/300（10.3%）。同 Qwen3-8B 后端下，Duopra 增益为 **+40.0 个百分点，配对 95% CI [31.3,48.7]**；主要新增成功来自基线未执行的 269 会话，其中 Duopra 通过 122 条，而非提升基线已调用子集的成功率。
2. **调用频率与完整执行是两件事。** 2a 令 Call 上升，但 Pass@1 仅 26.0→26.7，增益 CI 包含零；最终 Direct 达 47.7，较 RL1 **+21.0 [15.3,27.0]**。需 2–3 调用的成功率为 SFT 2.0%、RL1 0%、最终 27.5%。2b 同时变更数据、任务与奖励，不能把增益单独归因于某个奖励项。（`tables/tabA_ablation.tex`）
3. **更强后端并未显著提高整体成功率。** DeepSeek 相较 Qwen3-8B 的 Pass@1 增益为 +4.7 个百分点，CI **[−2.3,11.7]**，包含零；条件成功提高的同时 Call 下降，两者还条件化于不同会话子集。Both 下几乎不委托，因此也不足以证明已学会最优混合路由。（附录 F.1）

置信区间以录音为单位做 20,000 次配对 bootstrap，同一录音的 3 次解码始终成组；它不衡量不同训练随机种子的方差。Backend/Both 的事实回答延迟分别为 Qwen3-8B 14.85/10.42 秒、DeepSeek 13.60/9.95 秒，包含服务及工具时间，且权限暴露一并改变，不能当作委托本身的独立因果开销。

## 5. 对话保留与语音修复的证据

FDB v1.0 中，相对 RV-Audio，最终 Duopra 在用户说完后接话的 TOR 从 **59.1→75.6%**，在真实停顿中误抢话从 **18.1→5.4%**，打断后的接管指标从 **79.5→91.3%**。但并非所有体验都改善：接话延迟从 2.27 增至 2.75 秒，打断 TOR 也低于 SFT 的 97.0%。更关键的是，SFT、RL1、最终模型在 55 个测试项目上均**不再主动产生 backchannel（如“嗯、对”）**。FDB v1.5 中“听到用户附和后继续说”的 96.3% 衡量另一种行为，不能据此宣称主动附和恢复。（`tables/tabA_retention.tex`）

固定同一个 Duopra-RL thinker、文本和合成计划，仅替换 projector，中文 CER **6.01→2.58%**，英文 WER **9.74→7.66%**，支持低成本接口修复有效。但这是用于从四个候选中挑选 projector 的 **221 句选择集**（122 中文、99 英文），不是独立语音测试集。2,000 会话相同前缀回放中，talker 条件相对原始模型的平均余弦从 0.929 提升至 0.974，也只是表征对齐证据。（附录 F.4；`tables/tabA_stage3.tex`）

VoiceBench 九类平均从 37.9 升至 55.9，但 RV-Audio 的多数选择题输出未被解析，其基线分包含解析失败，不能把差值全部解释为底层知识或声学理解的提升。（附录 E.6、F.3）

## 6. 结论、局限与个人评价

**作者结论**：前端应学习忠实发起请求和完整执行任务；通过协议 SFT、全双工 RL 与 projector 修复，可以让任务执行与若干核心对话行为在一个因果策略中共存。

**我的评价**：最有价值的是完整的故障链条——是否发起、是否选对工具、参数是否忠实、步骤是否完成、回答是否有依据，以及训练后声音是否仍可懂。对类似模型训练，值得借鉴的是分开监控这些指标，加入更正/依赖/失败恢复任务，并在更新 thinker 后检查 thinker–talker 接口。

证据仍有明确边界：

- 仅验证一个语音基座，训练语音为有限音色的合成数据；工具测试仅 100 条英语录音和模拟 API，不能证明真实业务、多语言或开放环境中的稳健性。
- 用户输入和追问时机预先固定，无法评估真正由回答与工具结果触发的自适应多轮对话。附录所述澄清训练也受这个限制。
- 最终 Direct 仍有 58/300 会话工具集合正确但参数错误；字母 O/数字 0 等标识符混淆表明参数忠实度仍是重要瓶颈。
- 主动附和消失、接话延迟增加、语音修复仅有选择集结果，因此“保留所有双工能力”或“语音质量完全恢复”均超出证据。
- 2b 数据和奖励同时改变，Both 又几乎不用后端，缺少对奖励单项及动态路由的充分隔离。配置披露了主要超参数，但未列出 RL 两阶段总更新步数及完整端到端计算时长，尚不是完整可复现配方。

这篇论文支持“给双工语音前端训练任务能力，能解决特定管线中的大量未执行请求”；它尚未证明通用的、能长期维护任务状态的全双工智能体已完成。（正文结论与 Limitations；附录 F、G）
