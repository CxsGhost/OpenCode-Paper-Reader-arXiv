# Qwen-Audio 语音多模态预训练详解

> 面向全双工多模态模型预训练 & 模态对齐的参考文档

---

## 一、整体架构概览

Qwen-Audio 采用 **Audio Encoder + LLM** 的经典双塔结构：

```
原始音频 → Mel频谱图 → Audio Encoder (Whisper-large-v2) → Pooling → LLM (Qwen-7B) → 文本输出
```

### 关键设计选择

| 组件 | 具体选择 | 参数量 | 说明 |
|------|---------|--------|------|
| Audio Encoder | Whisper-large-v2 | 640M | 32层 Transformer + 2层卷积下采样 |
| LLM | Qwen-7B | 7.7B | 32层 Transformer Decoder, hidden=4096 |
| 连接方式 | 直接拼接 | - | Encoder输出直接作为LLM的输入序列 |
| Pooling | stride=2 | - | 减半音频表示长度，每帧≈40ms |

### 对你的启发

- **不需要额外的 Adapter/Q-Former**：Qwen-Audio 证明了直接连接 + 大规模训练可以完成模态对齐
- **单一 Encoder 处理所有音频类型**：不需要为语音、音乐、自然声音分别设计 Encoder
- Whisper 虽是 ASR 模型，但其编码的表示包含丰富的非语言信息（背景噪声、情感等）

### 2.2 数据处理关键点

**音频预处理流程：**
1. 重采样到 **16kHz**
2. 转换为 **80通道 Mel 频谱图**
3. 窗口大小 **25ms**，步长 **10ms**
4. 训练时使用 **SpecAugment** 数据增强（LibriSpeech Basic策略）
5. Pooling stride=2 → 每帧编码器输出对应原始音频约 **40ms**

## 三、训练策略详解（核心：模态对齐）

### 3.1 两阶段训练流程

```
阶段一：多任务预训练（Multi-task Pre-training）
├── 冻结 LLM
├── 只训练 Audio Encoder
├── 目标：让 Encoder 产生 LLM 能理解的表示（模态对齐）
└── 500k steps

阶段二：监督微调（Supervised Fine-tuning）
├── 冻结 Audio Encoder
├── 只训练 LLM
├── 目标：使模型遵循人类指令
└── 8k steps
```

### 3.2 为什么这样分阶段？

这是模态对齐的核心思想：

- **阶段一**：LLM 已有强大的语言理解能力。冻结 LLM，训练 Encoder 使其输出"像文本 token 一样"被 LLM 理解 → 这就是模态对齐
- **阶段二**：模态已经对齐，现在让模型学会"如何与人对话" → 指令跟随

### 3.3 训练超参数详解

| 配置项 | 阶段一（预训练） | 阶段二（SFT） |
|--------|-----------------|---------------|
| Audio Encoder 初始化 | Whisper-large-v2 | 阶段一训好的 |
| LLM 初始化 | Qwen-7B | Qwen-7B |
| 优化器 | AdamW | AdamW |
| β₁, β₂, eps | 0.9, 0.98, 1e-6 | 0.9, 0.98, 1e-6 |
| 峰值学习率 | 5e-5 | 1e-5 |
| 最小学习率 | 1e-5 | 1e-6 |
| Audio Encoder LR衰减 | 0.95 | 0（冻结） |
| LR 调度 | cosine decay | cosine decay |
| Weight decay | 0.05 | 0.05 |
| 梯度裁剪 | 1.0 | 1.0 |
| 训练步数 | 500k | 8k |
| Warm-up步数 | 2000 | 3000 |
| Global batch size | 120 | 128 |
| 梯度累积 | 1 | 8 |
| 精度 | bfloat16 | bfloat16 |
| 模型并行 | 无 | 2-way |

### 3.4 对小白的关键解读

1. **学习率**：阶段一用 5e-5，阶段二用更小的 1e-5，因为 SFT 需要更温和的调整
2. **训练步数差异巨大**：预训练 500k vs SFT 8k，模态对齐需要大量训练
3. **Batch Size**：120-128 是中等规模，实际有效 batch = 128 × 8(梯度累积) = 1024
4. **Encoder LR 衰减 0.95**：指的是 layer-wise learning rate decay，越底层的 Encoder 层学习率越低，保护预训练表示
5. **bfloat16**：混合精度训练，节省显存且数值稳定

## 四、多任务训练框架（解决模态对齐干扰问题）

### 4.1 核心问题：One-to-Many 干扰

不同数据集的文本标签差异很大：
- 任务目标不同（识别 vs 翻译 vs 描述）
- 语言不同（中英等8种）
- 标注粒度不同（有无时间戳）
- 文本结构不同（结构化 vs 非结构化）

**直接混合训练会导致模型困惑：同一段音频，期望的输出格式完全不同。**

### 4.2 解决方案：层级化条件标签（Hierarchical Tags）

Qwen-Audio 设计了一套层级 Tag 系统，告诉 Decoder 当前应该做什么：

```
<|startoftranscripts|> / <|startofanalysis|>   ← 转录标签
  → <|zh|> / <|en|> / <|unknown|>              ← 音频语言标签
    → <|transcribe|> / <|translate|> / <|caption|> / <|analysis|> / <|question-answer|>  ← 任务标签
      → <|zh|> / <|en|>                        ← 输出语言标签
        → <|timestamps|> / <|notimestamps|>    ← 时间戳标签
          → [输出指令]                          ← 进一步的格式说明
            → 文本输出开始
```

#### 各层标签详解

| 层级 | 标签 | 作用 |
|------|------|------|
| 1. 转录标签 | `<\|startoftranscripts\|>` / `<\|startofanalysis\|>` | 区分"精确转录"类任务 vs "分析"类任务 |
| 2. 音频语言 | `<\|zh\|>` `<\|en\|>` ... `<\|unknown\|>` | 标识音频中的语言；非语音用 unknown |
| 3. 任务标签 | `<\|transcribe\|>` `<\|translate\|>` `<\|caption\|>` `<\|analysis\|>` `<\|question-answer\|>` | 指明具体任务类型 |
| 4. 输出语言 | 同语言标签 | 指定输出文本的语言 |
| 5. 时间戳 | `<\|timestamps\|>` / `<\|notimestamps\|>` | 是否需要生成词级时间戳 |
| 6. 输出指令 | 自由文本 | 进一步指定子任务和输出格式 |

### 4.3 设计原则

- **共享标签促进知识共享**：相似任务共享前几层标签，使模型知道它们有共同基础
- **特定标签避免干扰**：后面层级的标签区分不同的输出格式
- **对 QA 任务**：在任务标签后追加具体的问题文本

### 4.4 对你的项目的启发

如果你做全双工多模态模型，需要处理多种类型的音频输入/输出，可以借鉴这种层级 Tag 设计：
- 先用粗粒度标签区分大的任务方向
- 再用细粒度标签区分具体的输出格式
- 这样模型在训练中既能共享底层表示，又不会被不同格式搞混

## 五、SRWT：词级时间戳预测的重要性

### 5.1 什么是 SRWT？

SRWT = Speech Recognition with Word-level Timestamps

训练模型在做语音识别时，同时预测每个词的起止时间：

```
<start_time_1> 词1 <end_time_1> <start_time_2> 词2 <end_time_2> ...
```

### 5.2 为什么重要？

实验证明 SRWT 带来多方面提升：

| 任务 | 没有SRWT | 有SRWT | 提升 |
|------|---------|--------|------|
| LibriSpeech test-clean (WER↓) | 2.22 | 2.04 | +0.18 |
| AISHELL1 test (WER↓) | 1.71 | 1.29 | +0.42 |
| ClothoAQA test (ACC↑) | 0.5648 | 0.5795 | +0.0147 |
| MusicAVQA (ACC↑) | 0.7027 | 0.7211 | +0.0184 |

### 5.3 为什么 SRWT 能提升其他任务？

- **强化时间对齐能力**：模型学会将音频信号的每个片段精确对应到具体内容
- **提升"grounding"能力**：不仅是语音，对自然声音和音乐的时间定位也更准确
- **本质上是一种辅助任务**：为主任务提供更好的音频表示

### 5.4 对你的启发

在做全双工模型的预训练时，加入时间戳预测作为辅助任务，可以显著提升模态对齐质量。

## 六、SFT（监督微调）阶段详解

### 6.1 数据构造

SFT 数据总量：**20k 条**（相对预训练来说非常少）

数据来源：
1. **人工编写的示例**：为每个任务人工编写问答示例
2. **GPT-3.5 扩展**：基于原始文本标签，让 GPT-3.5 生成更多问答对
3. **人工标注的对话数据**：包含推理、故事生成、多音频理解能力

### 6.2 对话格式

使用 ChatML 格式：

```
<im_start>user
Audio 1: <audio>path/to/audio.wav</audio>what does the speaker say?<im_end>
<im_start>assistant
The speaker says in English, "Won't you draw up, gentlemen."<im_end>
<im_start>user
What's the mood of the person?<im_end>
<im_start>assistant
Based on the voice, the mood of the person is disgusted.<im_end>
```

### 6.3 多音频支持

- 用 "Audio $id$:" 标记不同的音频输入
- 支持在一次对话中引用和讨论多段音频

### 6.4 混合训练

SFT 阶段同时使用：
- 音频相关的指令数据
- 纯文本指令数据

→ 保持模型的文本对话能力不退化

## 七、对你全双工多模态预训练项目的实操建议

### 7.1 模态对齐的核心路径

```
Step 1: 选一个强大的预训练 Audio Encoder（如 Whisper）
Step 2: 选一个强大的预训练 LLM
Step 3: 冻结 LLM，大规模训练 Encoder 输出对齐到 LLM 的表示空间
Step 4: 冻结 Encoder，SFT 训练 LLM 做指令跟随
```

### 7.2 数据建议

1. **量大是关键**：Qwen-Audio 用了约 130k+ 小时音频，多任务多语言
2. **数据多样性重要**：不要只用 ASR 数据，加入自然声音、音乐等多种类型
3. **辅助任务有用**：词级时间戳预测能显著提升模态对齐质量
4. **SFT 数据不需要太多**：20k 条高质量对话数据即可激活交互能力

### 7.3 训练技巧

1. **混合精度 bfloat16**：节省显存，推荐
2. **Layer-wise LR Decay（0.95）**：保护 Encoder 底层的预训练特征
3. **SpecAugment**：简单有效的音频数据增强
4. **Cosine LR Schedule**：配合足够的 warmup steps
5. **梯度裁剪 1.0**：稳定训练
6. **多任务时设计好条件标签**：避免 one-to-many 干扰

### 7.4 全双工场景的额外考虑

Qwen-Audio 是"半双工"的（先听完再生成），如果你做全双工：
- 需要额外考虑**流式音频编码**：不能等整段音频输入完
- 需要**打断机制**：用户随时可以插话
- 可能需要将 Encoder 改为**流式 Encoder**（如用 Conformer 替代全局 Transformer）
- 时间戳对齐能力对全双工尤其重要：模型需要知道"当前在听什么"

---

## 八、总结：关键 Takeaways

1. **模态对齐 = 让 Audio Encoder 说 LLM 的"语言"**：冻结 LLM 训练 Encoder 是最简洁有效的对齐方式
2. **多任务共训不是简单混合**：需要设计条件标签体系避免干扰
3. **SRWT 是被低估的辅助任务**：强化时间对齐能力，全面提升其他任务
4. **两阶段训练是标配**：先对齐，再微调
5. **单 Encoder 可以处理所有音频**：不需要按类型分多个 Encoder
6. **Whisper 是极好的初始化选择**：即使是 ASR 模型，其表示也包含了丰富的非语言信息
